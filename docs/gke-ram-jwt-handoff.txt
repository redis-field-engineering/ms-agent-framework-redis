Required wire contract

Authorization: Bearer <RAM agent key>
X-Iris-User-Token: <Cognito access token>

Keep the agent key as the primary credential. Its grants, roles, and tenant must
continue to determine store access. The user JWT supplies the personal UserID;
it must never expand the agent key's access. Do not replace this with direct
OIDC bearer authentication or the oidc_role_only compatibility mode.

behavior for agent keys without UserID. Do not infer capability from chart/tag
names alone. The local Iris source includes delegated-token commit ed31e9acf
(October 19, PR #1859); its docs/specs/MOD-19849-delegated-user-token.md and
memory/helm/README.md describe the contract. Reconcile these with the chosen
release's source, schema, migration notes, and known issues.

Determine compatible versions for the RAM data plane, worker, control plane,
identity service, and chart. Check migration and rollback requirements before

3. Prepare ownership enforcement and a coordinated cutover

This is a data-plane-wide setting, not a per-store switch.

Stage the upgrade and trust/delegation configuration first, leaving enforcement

The current smoke runner's memory_probe writes actorId iris-smoke using only the

4. Validation and return handoff

Run readiness/smoke checks after the staged rollout. Record actual image digests,
build metadata, chart versions, and non-secret effective authentication settings.
Prove the selected binary processes X-Iris-User-Token: with a valid agent key,
an invalid user JWT must be rejected rather than ignored.

With ownership enforcement on in an isolated validation deployment or during
the coordinated cutover, test two real, signed Cognito subjects:
- Each can create/read/list/search its own sessions and personal memories.
- Cross-user direct-ID access is denied and list/search do not leak foreign data.
- Creating personal data with a different owner/initial USER actor is rejected.
- Missing user JWT cannot read/write personal records; shared behavior may remain.
- Invalid/expired JWT, wrong audience, JWT without an agent key, and an agent key
  without permission to the target store fail as appropriate.
- Tenant mismatch is rejected when a valid signed mismatch can be exercised;
  otherwise identify it as untested. Do not alter the shared IdP to synthesize it.
- Worker processing and callbacks still work, including memory promotion.

Do not claim signed two-user checks passed without fresh tokens. If interactive
login is required, complete independent deployment checks and report the exact
remaining validation. Never persist user JWTs in committed configuration.
